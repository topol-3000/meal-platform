# 0008. PostgreSQL through SQLAlchemy async, asyncpg and Alembic; optional per service

- Status: Accepted (2026-10-26)
- Deciders: Yevhenii

## Context

meal-recipes, meal-planner and meal-shopping store data; meal-bot does not. Every service
that stores data should do it the same way, and a service without a database should carry
none of it. The reference project used Tortoise ORM.
Decisions D3 and D6 of the template's [architecture plan](https://github.com/topol-3000/meal-service-template/blob/main/docs/plans/architecture-guidelines.md).

## Decision

We use PostgreSQL through SQLAlchemy 2 (async, typed `Mapped[...]` style), the asyncpg
driver and Alembic migrations, traced by the OpenTelemetry SQLAlchemy instrumentation.
Repositories implement domain ports and map rows to domain objects (ADR 0007).
Relationships use `lazy="raise"`. The transaction boundary is the request: one session and
one transaction per request, committed before the response is sent. There is no Unit of
Work; we revisit that when a use case needs a transaction boundary of its own.

The database is a template option, `with_database` (default `true`). Without it, the
service has no database code, settings, migrations or dependencies, and still passes
`make check`.

## Alternatives

- **Tortoise ORM** (the reference project). A smaller ecosystem, weaker static typing, and
  migrations through a separate tool (aerich) instead of Alembic's autogenerate.
- **Plain asyncpg with SQL.** Fewest layers, but no typed mapping and no autogenerated
  migrations; every query is a string to keep in sync with the schema.
- **SQLModel.** One class for table and API model, which is exactly the coupling ADR 0007
  avoids.
- **Unit of Work now.** Not needed while one request is one transaction.

## Consequences

- SQLAlchemy is capped below 2.1 until the OpenTelemetry instrumentation releases support
  for it (the plan's follow-up F1).
- Async SQLAlchemy needs care (no lazy loading, `expire_on_commit=False`); the template's
  `docs/conventions/persistence.md` holds the rules.
- Services with a database need Docker for their integration tests (ADR 0011).
